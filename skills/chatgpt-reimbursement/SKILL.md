# ChatGPT订阅报销

使用中文。处理用户本次指定的月份和凭证，默认保存草稿，未明确要求时不提交审批。不将此Skill视为访问邮箱、上传文件或提交流程的新授权；以当前用户请求为准。

## 固定偏好

- Excel只保留“填写说明”和本次实际报销月份的Sheet。删除历史月份，排除本次取消的月份，不仅隐藏Sheet。
- 严格沿用模板的字体、列宽、行高、边框、合并单元格、数字格式和打印设置。仅更新内容和必要日期行；不美化、不整表自动调整行列。
- 每个月的明细附件为一份对应PDF收据和一份信用卡扣费记录。按人民币实际扣费填写，不把日元金额直接作为人民币金额，不把礼品卡充值与订阅再次重复报销。
- 费用月份、扣费日期、入账日期、订阅起止日期分别核对。跨月订阅按凭证及用户确认填写，不默认包含未来月份。
- 用户缩小范围时，同步核对流程明细、主题、总额、Excel页签和汇总附件。保留用户已做的修改，不重建或覆盖其草稿。

## 工作流程

1. 核对月份、每笔金额、周期、凭证和文件位置。没有用户指定的新模板时使用[保存的Excel模板](assets/报销汇总模板.xlsx)。参考最近报销流程；复制流程时仅修改新单，避免操作背景中的原单。
2. 项目分摊需要时，读取用户本次授权范围内的周报，记录工时和口径，排除休息、休假及非项目培训。不得沿用旧单比例，或将工时估算写成已核实的AI使用时长。按用户确认的自然月或周期计算，每月合计100%，说明必要尾差和数据截止日；缺少依据时先完成独立工作，再询问必要信息。
3. 使用可用的表格技能处理模板。每次复制模板生成本次文件，不覆盖Skill中的模板。参见下方约定。需读取PDF时使用PDF技能；票据保持原件，不修改票面信息。
4. 优先使用当前可用的服务工具或后台浏览器处理已登录网页，能力不足再用当前环境支持的浏览器操作。需要登录时交给用户。不要把口令、验证码、Cookie或临时签名链接存入Skill。
5. 下载先尝试一次适当方法；超时后检查是否已下载或弹出保存框，避免盲目重复。仍不可用时，按用户偏好把每份真实PDF分别在内置浏览器打开，核实文件名及内容后交给用户手动保存。不得拼接、猜测签名URL；不未经说明占用桌面鼠标。
6. 在当前草稿逐行填写并上传对应凭证；额外发票原件上传到汇总附件区。旧汇总Excel和无关旧票据不能混入新单；原申请邮件等按实际适用性保留。用户已删除的项目先核对，不重复删除。操作超时先观察是否已生效，再继续。
7. 保存后核对月份/周期、各笔金额和总额、项目比例、每行两份凭证、汇总表及额外发票、待提交状态。Excel与流程金额一致。简要报告保存及提交状态，并提供可核对结果。

## 模板约定与检查

- `assets/报销汇总模板.xlsx`含“填写说明”和空白的“月度报销模板”，保留刘涛、DES等既有表头。申请人、公司、部门、关联项目和经理以本次流程为准，模板默认值不替代核对。
- 每月复制模板并命名，如“8月报销表”。日期/星期从第6行开始；模板预留31天，合计第37行，说明第38行。按实际天数调整日期区和合计公式，沿用相邻行格式，不保留无效日期。
- A列日期、B列星期、E列归属项目、AD列“其它费用—其他”、AE列备注、AF列当日合计。费用放在真实扣费日期行，金额栏目遵循用户最近确认的原表惯例，不自行改变费用性质。
- 日期写成Excel数值日期并按原模板显示`yyyy/m/d`。曾发生JS Date导出为`2026-08-01T00:00:00.000Z`文本的故障：不能只看内存渲染，必须检查最终XLSX中的日期确为数值，正常列宽下单行显示；需要时使用Excel日期序号。
- 写入后重算，核对日/月合计。读取最终导出文件，确认仅有说明页和本次月份；渲染核对日期、行高、表头及金额。对照模板检查关键样式、打印设置和合并区域，不能用“导出成功”代替保真验证。
- 工具不能保留某项格式时，优先采用保留原文件其余结构的局部处理并验证差异，不重新绘制整张表或默默改变格式。

每次重新读取本次月份、金额、凭证和项目依据。历史金额、比例、发票额度和流程ID不作为固定值。
